## 🎯 프로젝트 개요

### 💡 시스템 개요

5가지 문서 타입(Invoice, Receipt, Resume, Report, Contract)을 AI로 자동 처리하는 시스템

```
┌─────────────────────────────────────────────────────────────┐
│                 Input: 이미지/PDF 문서                        │
└─────────────────────┬───────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 1: OCR-VL (PaddleOCR)                                  │
│  • 텍스트 추출                                                │
│  • 레이아웃 분석 (제목, 테이블, 키-값 쌍)                       │
└─────────────────────┬───────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 2: 문서 분류 (DistilBERT)                               │
│  • invoice, receipt, resume, report, contract 중 판별         │
└─────────────────────┬───────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 3: LLM 처리 (Ollama + Qwen2.5)                         │
│  • 구조화 데이터 추출 (invoice/receipt/resume)                │
│  • 문서 요약 (report/contract)                                │
│  • PII 탐지 (개인정보)                                         │
└─────────────────────┬───────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────────────┐
│                 Output: JSON 결과                            │
└─────────────────────────────────────────────────────────────┘
```

### 🎤 주요 기능

1. **OCR + 레이아웃 분석**
   - PaddleOCR 기반 텍스트 추출
   - 문서 구조 분석 (제목, 테이블, 밀도)
   - 신뢰도 91%+

2. **자동 문서 분류**
   - DistilBERT 기반 학습
   - 레이아웃 정보 활용
   - 정확도 90%+

3. **스마트 추출**
   - Qwen2.5:7b LLM 사용
   - 문서 타입별 맞춤 추출
   - 오픈소스 (Apache 2.0)

4. **PII 탐지**
   - Regex + LLM 하이브리드
   - 이메일, 전화번호, ID, 이름, 주소
   - 태국 특화

### 4.2 Classification Module (`srcs/classification_module.py`)

**역할:** 문서 타입 분류 (5개 클래스)

**클래스:**
```python
labels = ['invoice', 'receipt', 'resume', 'report', 'contract']
```

**학습 프로세스:**
1. labels.csv + OCR 결과 로드
2. Enhanced text 생성 (텍스트 + 레이아웃)
3. Tokenization (최대 512 토큰)
4. DistilBERT fine-tuning (3 epochs)
5. 모델 저장

**분류 과정:**
```python
text → tokens → model → logits → softmax → argmax → doc_type
```

**왜 DistilBERT?**
- BERT의 40% 크기
- 60% 빠른 추론
- 97% 성능 유지

### 4.3 Smart Extractor (`llm_service/extractors/smart_extractor.py`)

**역할:** LLM 기반 구조화 데이터 추출

**지원 문서:**
- invoice: vendor, invoice_number, date, total_amount, currency
- receipt: store, date, total, currency
- resume: name, experience, education, skills
- report: title, date, key_findings (요약으로 대체)
- contract: parties, effective_date, key_terms (요약으로 대체)

**핵심 로직:**
```python
def extract(self, filename, full_text_ocr, layout, doc_type):
    # 1. Schema 선택
    schema = self.schemas[doc_type]
    
    # 2. Prompt 생성 (text + layout.sections)
    prompt = self._build_prompt(full_text_ocr, layout, schema)
    
    # 3. Ollama API 호출
    response = self._call_ollama(prompt)
    
    # 4. JSON 파싱
    return self._parse_json_response(response)
```

**모델:** Qwen2.5:7b
- 다국어 지원 (태국어 포함)
- 일관된 JSON 출력
- Apache 2.0 라이선스

### 4.4 PII Detector (`llm_service/extractors/pii_detector.py`)

**역할:** 개인정보 탐지 (하이브리드 방식)

**탐지 타입:**
1. **Regex 기반**:
   - EMAIL: `[\w\.-]+@[\w\.-]+\.\w+`
   - PHONE_NUMBER: `\+?\d{1,3}[-.\s]?\(?\d{1,4}\)?[-.\s]?\d{1,4}[-.\s]?\d{1,9}`
   - THAI_ID: `\b\d{1}-\d{4}-\d{5}-\d{2}-\d{1}\b`
   - CREDIT_CARD: `\b\d{4}[-\s]?\d{4}[-\s]?\d{4}[-\s]?\d{4}\b`

2. **LLM 기반**:
   - PERSON_NAME (이름)
   - ADDRESS (주소)

**출력 형식:**
```json
{
  "type": "EMAIL",
  "value": "john@example.com",
  "confidence": 0.95
}
```

  }

### 필드 설명

| 필드 | 용도 |
|------|------|
| `filename` | 파일 식별 |

| `layout.title` | 컨텍스트 |
| `layout.sections` | 키-값 쌍 정보 |
| `layout.features` | 구조 이해 |
| `classification.doc_type` | 추출 전략 결정 |

invoice:

contract:
  - 주요 조항 요약

**보너스 기능:**
- PII 탐지 (이름, 주소, 전화번호)

## 🎓 기술적 배경

### 왜 PaddleOCR-VL인가?

**기존 방식:**
```
PaddleOCR (텍스트만)
  텍스트: "Total: 1500 USD"
  위치: 없음
  → 정확도: ~85%
```

**개선 방식:**
```
PaddleOCR-VL (텍스트 + 레이아웃)
  텍스트: "Total: 1500 USD"
  위치: (100, 450) - 하단
  구조: Key-value, 테이블 근처
  → 정확도: ~95%
```

---

### DistilBERT 학습 원리

**Step 1: 데이터 준비**
```
doc001.jpg → OCR → "INVOICE ABC Corp" → Label: invoice
doc002.jpg → OCR → "Receipt Store" → Label: receipt
(500-1000개)
```

**Step 2: 학습**
```
Epoch 1: "INVOICE" → 80% invoice (불확실)
Epoch 2: "INVOICE" → 92% invoice (확신)
Epoch 3: "INVOICE" → 96% invoice (확실)
```

**Step 3: 가중치 업데이트**
```
"INVOICE" → [9.5, 0.3, 0.1, 0.1, 0.0]
             invoice^^ 높음!
```

## ❓ FAQ

### Q1: GPU 없으면?
**A:** `--gpu` 옵션 제거. CPU로 작동하지만 2-3배 느림.

### Q2: 가상환경이 안 활성화되면?
**A:**
```bash
rm -rf venv
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### Q3: OCR 신뢰도가 낮으면?
**A:**
1. 이미지 품질 확인
2. 회전 보정 (`use_angle_cls=True`)
3. 신뢰도 < 70%는 수동 확인
4. LLM이 오류 수정하므로 너무 걱정 안 해도 됨

### Q4: 학습 시간이 오래 걸리면?
**A:** Epochs 감소
```python
# srcs/classification_module.py
num_train_epochs=3  →  num_train_epochs=2
```

### Q5: Ollama 타임아웃?
**A:** 정상. CPU 모드는 60-90초/문서. 로컬 실행 추천.

### Q6: Docker vs 로컬?
**A:**
- **개발/테스트**: 로컬 (Metal 가속, 빠름)
- **제출**: Docker GPU (CUDA 가속)
- **백업**: Docker CPU (느림)
